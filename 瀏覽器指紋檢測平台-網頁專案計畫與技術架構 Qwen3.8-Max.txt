五、關鍵技術挑戰與解決方案
🔴 挑戰 1：Canvas 篡改偵測
問題： Brave/Tor 等瀏覽器會修改 Canvas 輸出以保護隱私 
github.com

方案：
多重繪製策略：同一段文字繪製多次，比對結果一致性
離屏 Canvas vs 在屏 Canvas 交叉驗證
偵測 toDataURL() 和 getImageData() 的調用頻率
🔴 挑戰 2：UA 與真實 OS 不一致
問題： 模擬器/指纹浏览器可能偽造 User Agent（如報告中 Android 10 vs 14）
方案：

123456偵測策略：├── navigator.userAgentData (Client Hints API)├── navigator.platform vs userAgent 比對├── WebGL 渲染器資訊 (Adreno 613 對應特定 OS 版本)├── navigator.connection.effectiveType (網路類型)└── Battery API / Permissions API 狀態
🔴 挑戰 3：WebRTC 洩漏偵測
問題： VPN 用戶的真實 IP 可能透過 WebRTC STUN 洩漏 
www.expressvpn.com

方案：
後端部署多個 STUN 伺服器 (Google STUN + 自建 TURN)
客戶端輪詢不同 STUN，比對返回的 IP 列表
比對 RTCPeerConnection 返回的 local IP 與公網 IP
🔴 挑戰 4：DNS 洩漏檢測
問題： 用戶可能不知道自己的 DNS 請求走了真實 ISP
方案：
後端建立「DNS 誘捕域名」(如 detect.ourdomain.com)
前端加載子域名資源，後端記錄查詢來源
比對來源 IP 是否與公網 IP 屬於同一 ISP
🔴 挑戰 5：Port Scan 的精確性
問題： 客戶端環境不允許主動端口掃描（瀏覽器沙盒）
方案：
後端根據客戶端來源 IP，從多個地理位置反向掃描
使用 nmap 搭配 TCP SYN 掃描（半開掃描）
結果快取，避免重複掃描同一 IP
